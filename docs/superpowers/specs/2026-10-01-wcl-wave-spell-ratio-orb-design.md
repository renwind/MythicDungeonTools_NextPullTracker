# WCL 每波技能配比圆球设计

## 目标

将参考 WCL 中元素萨满每个最终 MDT/NPT 波次的元素冲击与地震术成功施法次数导入插件，并在钥匙中随当前波次显示历史打法倾向。该功能只展示导入的历史数据，不统计当前实战。

## 统计口径

- 元素冲击：spell ID `117014`。
- 地震术：spell ID `61882`。
- 只统计 WCL 中成功完成的 `cast` 事件，不统计 `begincast`、失败或被打断施法。
- 每条事件使用与冷却计划相同的最终波次时间区间归属规则。
- 圆球液位使用原始次数计算精确比例：`elementalBlast / (elementalBlast + earthquake)`。
- 文本归一化到十等分：`elemental = floor(exactRatio * 10 + 0.5)`，`earthquake = 10 - elemental`，显示为 `8:2`，不显示百分号或施法次数。

## 导出数据流

WCL 数据采集阶段向 CLI 输入增加 `rotationCastEvents`：

```json
[
  { "type": "cast", "spellId": 117014, "t": 161.048 },
  { "type": "cast", "spellId": 61882, "t": 165.422 }
]
```

导出器强制校验 `type === "cast"` 与上述两个 spell ID；`begincast`、失败事件和其他技能不会被当作有效输入。

CLI 完成最终分波后，将这些事件按 `waves[].castStart/castEnd` 归属并生成：

- `summary.rotationUsage`：每波 `{ elementalBlast, earthquake }` 原始次数。
- `importratiopack.txt`：游戏内导入命令。
- 报告波次表中的配比列，用于人工核验导出与游戏内结果一致。

任何无法归属的配比事件都使 CLI 失败，不静默丢弃。报告会根据持久化的事件与最终波次重新计算 assignments 和 usage，拒绝内部自相矛盾但文件彼此一致的产物。

## 导入格式

新增独立命令，避免改变现有 `/npt importplanpack` 冷却计划语法：

```text
/npt importratiopack <routeKey> 0.q,1.16,1.19
```

规则：

- 每个 token 是 `<元素冲击次数base36>.<地震术次数base36>`；token 顺序就是波次顺序。例如 `q`=26、`16`=42。
- 次数必须是非负安全整数；只接受小写 base36。
- 导出器为每个波次写一个 token，包括 `0.0`，以区分“已导入但该波无施法”和“没有导入数据”。
- 解析器先验证 routeKey、token 数等于路线波数以及全部次数，再原子写入；任一错误时整包拒绝。
- 导出器拒绝超过 WoW 聊天框 255 字符限制的命令，不生成无法粘贴的产物。

## 存储模型

角色库新增：

```lua
rotationRatios[presetUID][pullIndex] = {
  elementalBlast = 0,
  earthquake = 26,
  fingerprint = "1:5,2:15,3:4",
}
```

配比数据与冷却计划分开存储，但使用相同的路线 UID、波次编号和 pull fingerprint 约束。路线内容漂移后不显示旧配比，避免数据串波。切换角色专精不会删除数据。

## 游戏内圆球

新增独立 `SpellRatioOrb` 窗口：

- 默认位于 NPT Plan 右侧，之后相对 `UIParent` 保存用户位置。
- 默认点击穿透；按住 Alt 后允许左键拖动，松手持久化位置。
- 按住 Alt 时显示右下角缩放把手；拖动把手以 `0.5–2.0` 范围等比缩放整个窗口，圆球、技能图标和比例文字保持相对布局不变。
- 缩放值保存到账号级 `db.beacon.spellRatioOrbScale`；创建窗口时恢复并夹到合法范围。缩放中松开 Alt 会立即结束缩放、保存比例并恢复点击穿透。
- 使用圆形遮罩裁剪两个矩形色块，形成暗黑式能量球。
- 上方电光紫 `#B34CFF` 代表元素冲击，下方岩土金 `#C9902E` 代表地震术；元素冲击占比四舍五入到最近的 10% 档位，地震术取补数。两技能都非零时液位限制在 10%–90%，因此 `2%→10%`、`14%→10%`、`15%→20%`；单侧为零时仍允许 `0%/100%`。
- 球下仍显示原十等分比例文本，例如 `8:2`；文字不应用非零保底，因此 `1/46` 的液位是 `10:90`，文字仍为 `0:10`。
- 占比较高的技能图标显示在圆球右上方。
- 两项原始次数相等时两个技能图标并列；不能仅因取整结果恰好为 `5:5` 而判定相等。
- 已导入的 `0:0` 波显示暗色空球，但不显示图标和文字。
- 未导入数据、路线 fingerprint 不匹配、未开始追踪或当前角色不是元素专精时隐藏整个窗口。
- 设置面板提供独立开关，默认开启。

建议初始尺寸为 64×64 像素，图标为 20×20 像素；语义颜色固定为元素冲击紫色和地震术橙色，外圈使用当前主题强调色。

## 更新时机

`MDT_NPT:UpdateAll()` 是常规刷新入口。开始/停止追踪、自动推进、手动跳波和回退均通过该入口调用 `SpellRatioOrb:Update()`；配比导入成功及玩家专精变化时也立即刷新。窗口不需要独立高频 ticker，因为展示的是静态历史数据。

## 模块边界

- `tools/wclplan`：识别两种技能、按最终波次计数、输出 summary 与导入命令。
- `SpellRatioData`：存储、清洗、fingerprint 验证。
- `ImportRatio`：解析命令、routeKey 校验和原子写入。
- `SpellRatioOrb`：读取当前 preset UID 与 pull index，计算显示比例并渲染窗口。
- `Settings`、`Slash`、加载清单和默认数据库只负责接线。

## 异常处理

- 缺少 `rotationCastEvents`：CLI 明确报错，不把缺失数据解释成零次。
- 有事件无法归属：CLI 失败并列出时间。
- routeKey 不匹配：游戏内拒绝整包导入。
- 存档字段损坏：删除该波无效记录并只警告一次。
- 圆形遮罩使用 WoW 12.1 已保证存在的 `MaskTexture` API，不增加不可验证的兼容降级路径。

## 验证

### Node 测试

- 只计成功 `cast`，忽略 `begincast`。
- 按 boss-entry 与 confirmed-combat 最终边界正确归属。
- 边界时刻使用与冷却施法相同的归属规则。
- `rotationUsage`、命令文本和报告一致。
- 未归属事件、非法技能和非法次数失败。

### Lua 测试

- `importratiopack` 正确解析顺序式 base36 token，并拒绝坏格式、波数不匹配和 routeKey 不匹配。
- 校验失败不产生部分写入。
- `0:0`、`5:5`、单侧 100% 与一般比例计算正确。
- 圆球液位按最近 10% 档位绘制，两技能都非零时各自至少一档；十等分文字保持原算法。覆盖 `1/46 → 液位 10:90、文字 0:10`、`14%→10%`、`15%→20%` 与单侧 `0:100`。
- 路线 fingerprint 漂移后隐藏。
- 当前波推进、跳波、回退与停止追踪刷新正确。
- 非元素专精隐藏。
- Alt 拖动、点击穿透和位置恢复正确。
- Alt 缩放把手仅在交互态可用；缩放范围、整体等比缩放、松 Alt 收尾以及 `/reload` 后比例恢复正确。
- 圆球色块高度、图标显隐和比例文本符合设计。

### 游戏内验证

- 导入一套已知 WCL 配比后逐波使用 `/npt alert` 或手动跳波核对。
- 验证默认位置位于 NPT Plan 右侧，拖动后 `/reload` 保持位置。
- 验证两种极端比例、`5:5` 和 `0:0` 的视觉结果。
